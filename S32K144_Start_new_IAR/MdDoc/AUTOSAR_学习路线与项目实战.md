# AUTOSAR / S32K144 学习路线与项目实战指南

> 面向目标：**找汽车电子嵌入式（BSW / 底层软件 / AUTOSAR 工程师）岗位**
> 环境：S32K144 + Vector MICROSAR (CBD1800257) + DaVinci Configurator + IAR
> 节奏假设：业余每天 2~3 小时，全程约 8~10 周

---

## 0. 核心心态：项目驱动，不要单点学配置

单纯在 DaVinci 里一个个点配置项，会觉得枯燥且容易忘。正确姿势是：

> **先挑一个"有现象"的小目标 → 做的时候卡在哪，再回头补那块理论和配置。**

判断标准很简单：**这个知识点做完，我能不能看到现象？**
- 能看到（灯亮、波形、CAN 报文、复位重启、掉电不丢）→ 优先做
- 看不到（纯概念）→ 放到项目里顺带理解

参照例子：排查 SPI 数据偏位时，从"MOSI 跟着 Send[] 变"一路推到"CONT_EN 导致分析仪字对齐偏位"——这种调试过程比看十集视频有用得多，也是面试时最拿得出手的经历。

## 1. 资源地图：S32K144 项目/例程去哪里找

### 1.1 NXP 官方（最权威，优先挖这里）

| 资源 | 内容 | 怎么用 |
|---|---|---|
| **S32 Design Studio (S32DS) for ARM** | 自带 S32K144 SDK Examples，几百个：`flexcan_*`、`lpspi_transfer`、`adc_*`、`ftm_pwm`、`pdb_*`、`wdog_*` | 新建工程时选 "New Project from Example"，每个外设都有裸机例程，可和 MICROSAR 配置一一对照 |
| **S32K1xx RTD (Real-Time Drivers)** | NXP 官方 AUTOSAR 兼容驱动包（含 MCAL 层驱动 + 示例） | 想看"官方 MCAL 怎么写的"就挖它 |

| **NXP Application Notes (AN)** | AN5413 时钟计算、AN12260 等 | 针对性补知识点 |
| **NXP Community**（community.nxp.com） | 搜 `S32K144`，大量实战帖 / 踩坑记录 | 卡住时的第一站 |

## 2. 学习路线总览

### 2.1 顺序（即优先级）

```
补漏 GPT → 第7章 OS → 第4章 Application → 第10章 UDS → 第9章 NVM
        → 第5章 BCM项目(四步走) → 第11章 E2E → 第12章 BMS(科普) → 扩展 + 投简历
```

### 2.2 分阶段计划

| 阶段 | 内容 | 时长 | 产出 |
|---|---|---|---|
| **一** | **GPT（定时器）+ 第7章 OS**：Task 分类（Basic/Extended）、调度策略（抢占/协作）、一类/二类中断、Resource 优先级天花板、Alarm + Counter | 2 周 | MdDoc：GPT 篇 + OS 篇 |
| **二** | 第4章 Application：RTE 深入（Runnable 触发源全类型、IRV、Port 接口选型） | 3~4 天 | 在 Swc0/Swc1 上试新触发方式 |
| **三** | **第10章 UDS**：CanTp 分段传输 + 诊断服务（$10/$22/$2E/$27/$34/$36/$37） | 2 周 | MdDoc：CanTp 篇 + UDS 篇 |
| **四** | 第9章 NVM：Nvm / FEE / MemIf / Fls 四层栈 | 1 周 | MdDoc：NVM 篇 |
| **五** | **第5章 BCM 项目 四步走**（车窗 / 转向灯联合编译） | 2 周 | 简历项目成型 |
| **六** | 第11章 E2E（概念 + CRC/AliveCounter 机制）+ 第12章 BMS（1.5 倍速科普，**不做项目**） | 1 周 | 概念能讲 |

> **BMS 说明**：BMS 那章只有框架和概念讲解、没有可做的项目，门槛在电池算法而非嵌入式通信，个人做出来也是 toy。当行业科普听一遍即可。**课程真正的项目就是第 5 章 BCM 联合编译那两个（车窗、转向灯）。**

## 3. BCM 项目：四步走（重点，别跳过）

别看它小，它是唯一让你经历**完整工程闭环**的项目：

```
应用层 SWC（车窗/转向灯逻辑）
   ↔ RTE 连接（Port / Runnable / 事件）
   ↔ BSW 联调（Dio / Pwm / Adc / Can 全被牵进来）
   ↔ 编译链接（联合编译踩坑）
```

很多人学完单模块就停，一联编全是错：RTE 没重生成、MemMap 缺失、任务没挂 Runnable……**这些坑只有联编才会暴露**，面试官一问"你集成过吗"就露馅。

| 步骤 | 目标 | 天数 |
|---|---|---|
| ① **跑通** | 编译过、车窗/转向灯功能正确；每个报错都要搞懂原因 | 2~3 天 |
| ② **看懂** | 画出 `Dio → SWC → RTE → Pwm` 完整数据流；能讲清"谁触发这个 Runnable、信号走 S/R 还是 C/S" | 1~2 天 |
| ③ **魔改** | 加双闪（两灯交替）/ 一键升降 / 防夹（ADC 采电流判断）——逼你动 DaVinci 配置、加 Runnable、调 RTE | 3~4 天 |
| ④ **扩展** | 加 CAN 状态上报 + 看门狗监控 + NVM 存位置 + UDS 诊断 → **变成简历项目** | 4~5 天 |

### 扩展清单（每加一项都是一个面试知识点）

| 加什么 | 用到课程 | 面试卖点 |
|---|---|---|
| CAN 周期上报车窗状态 | 第 2 章 CAN 栈 | 通信集成经验 |
| 看门狗监控车窗/转向灯 SWC | 第 6 章 WdgM | Alive / Logical 监控实践 |
| NVM 存车窗位置记忆 | 第 9 章 NVM | 存储栈经验 |
| UDS 诊断（读故障 / 控制车窗） | 第 10 章 UDS | **诊断，核心卖点** |
| OS 多任务重排（不同周期 Runnable 分开） | 第 7 章 OS | 调度理解 |

## 4. 六个"有现象"的小项目（破枯燥专用）

按顺序做，每个都能立刻看到效果，每个做完沉淀一篇 MdDoc 笔记。

| # | 小项目 | 用到的知识 | 验收标准（现象） |
|---|---|---|---|
| 1 | PWM 呼吸灯 + 电位器调速 | Dio / Pwm / Adc | 灯亮度随电位器实时变化 |
| 2 | SPI 读写 UJA1169（SBC） | SPI EB / CS 时序 | 逻辑分析仪抓到正确字节序列，能读出 SBC 寄存器 |
| 3 | CAN 周期上报 ADC 值 | CAN / Com / RTE | 上位机（CANoe/PCAN）收到周期报文，值随电位器变 |
| 4 | 看门狗"故意不喂狗" | Wdg / WdgM | 板子自动复位；用 `RCM_SRS` 读到复位原因 |
| 5 | NVM 存参数、掉电重读 | Nvm / Fls | 断电再上电，参数仍在 |
| 6 | UDS 用上位机发 `10 03` | UDS / CanTp | 上位机收到正响应 `50 03 ...` |

> 做完 1~6，你已经把 MCAL 大部分模块 + CAN + Wdg + NVM + UDS 全部"跑通过一遍"，此时再去啃 BCM 联编会轻松很多。

## 5. 每天怎么学（2~3 小时模板）

```
1.0 h  看视频（1.25~1.5 倍速，带着问题看：这模块解决什么问题？）
1.0 h  动手（工程里配一遍 / 改代码 / 跑起来）   ← 权重最高
0.5 h  记笔记（当天写进 MdDoc，趁热写）
```

**每周日加一条自测**：合上笔记，把本周学的模块用嘴讲一遍。讲不顺的地方就是没懂，下周补。这比重看视频高效得多。

---

## 6. 防弃坑三条纪律

1. **每天动手时间 ≥ 视频时间**——只看视频不动手，两周后全忘
2. **笔记不过夜**——当天学的当天写进 MdDoc，攒到周末 = 不写
3. **卡住超 2 小时就问 / 就跳过标记**——别在一个报错上耗一晚上，标记后先推进，很多坑回头看就懂了

## 7. 投简历时机与简历写法

### 7.1 时机

**第 6~7 周**（UDS 学完 + BCM 扩展做完）就可以开始投，不必等全部学完。
此时已具备：MCAL 全模块 + CAN + 看门狗 + OS + UDS + NVM + 完整项目。
E2E / BMS 边面试边补——**面试挂掉的知识点就是你下一轮的补课清单**。

### 7.2 岗位关键词

```
汽车电子嵌入式开发 / BSW 工程师 / AUTOSAR 工程师 / 底层软件工程师
```
主要去向：主机厂与供应商（博世、联电、纬湃、东软睿驰、中科创达等）、新势力供应链。

### 7.3 简历项目描述模板（可直接改用）

> **基于 AUTOSAR CP 架构开发车身控制节点**：应用层实现车窗 / 转向灯控制逻辑（含防夹、双闪），BSW 集成 CAN 通信、看门狗监控、NVM 存储与 UDS 诊断，完成 RTE 联合编译与整车功能调试。

完成全部路线后，你会得到：

1. **一整套 MdDoc 笔记**（现有 5 篇：看门狗栈 / SPI / ADC / CAN 栈 / MCU 时钟，再加 GPT、OS、CanTp、UDS、NVM）

这就是这套课程的完整变现路径。
