## 1. 推荐学习顺序（BSW 视角，不照搬目录编号）

> 目录编号是"录制顺序"，不一定是最优学习顺序。下面是按**依赖关系 + 求职价值**重排的主线。

```
主线：
  1 → 2 → 3 → 4 → 5(第一轮跑通) → 7 → 6 → 8 → 9 → 10 → 11 → 5(扩展成项目) → 12 → 13

分阶段：
  阶段一（建立认知）    1
  阶段二（通信基础）    2
  阶段三（驱动核心）    3          ← BSW 立身之本
  阶段四（应用层接口）  4 → 5(跑通)
  阶段五（系统核心）    7 → 6      ← OS 要先于看门狗（原因见下）
  阶段六（网络管理）    8
  阶段七（存储与诊断）  9 → 10     ← 求职差异化技能
  阶段八（安全通信）    11
  阶段九（项目落地）    5(扩展)   ← 简历项目成型
  阶段十（行业认知）    12 → 13
```

### 为什么这样排（三个关键调整）

| 调整 | 原因 |
|---|---|
| **7（OS）排在 6（看门狗）之前** | 看门狗的 `WdgM_MainFunction` 必须挂在 OS 周期任务上，不懂 Task/Alarm 直接学看门狗会一头雾水 |
| **10（UDS）优先级提到最高档** | 武汉 BSW 岗位 JD 里 UDS + Bootloader 出现频率最高、候选人最少，是**薪资分水岭** |
| **5（BCM 联编）学两轮** | 第一轮跑通练手，最后一轮扩展成完整项目（加 CAN/Wdg/NVM/UDS），才是简历上的项目 |

### BSW 岗位优先级标注

| 章节 | 对 BSW 的重要性 | 说明 |
|---|---|---|
| 3、7 | ⭐⭐⭐ **必精通** | MCAL + OS 是 BSW 的吃饭本事 |
| 2、6、8、9、10、11 | ⭐⭐ **必须会** | CAN 栈 / 看门狗 / 网络管理 / NVM / UDS / E2E 是标准 BSW 模块 |
| 4、5 | ⭐ **要懂接口** | BSW 不写业务，但必须懂 SWC/RTE 接口才能联调 |
| 1、12、13 | ◇ **了解即可** | 行业认知与架构视野 |

## 2. 每章学习目标（含动手验收标准）

### 阶段一：建立认知

#### 第 1 章 · 汽车嵌入式与 AUTOSAR 介绍

| 项 | 内容 |
|---|---|
| **学习目标** | 说清 AUTOSAR 为什么存在；画出 CP 分层架构（ASW / RTE / BSW / MCAL）；理解 BSW 内部分层（Services / ECU Abstraction / Complex Drivers） |
| **动手验收** | 能对着自己工程目录指出每一层代码在哪 |
| **BSW 要点** | 记住 BS**W 四层划分**——这是面试第一个问题 |
| **过关判据** | 合上笔记，能 3 分钟讲清"一个信号从 SWC 发出到 CAN 总线"要经过哪些层 |

---

### 阶段二：通信基础

#### 第 2 章 · CAN 协议栈

| 项 | 内容 |
|---|---|
| **学习目标** | 掌握 Signal / I-PDU / L-PDU 三级概念；说清 Com → PduR → CanIf → Can 的路由链；懂 HTH/HRH 硬件句柄 |
| **动手验收** | 配一条周期报文，用 CAN 盒在上位机收到；改一次周期值看现象变化 |
| **BSW 要点** | 理解 **MDT（最小延迟时间）**、字节序、TxMode（周期/事件） |
| **过关判据** | 能回答"为什么我 `Rte_Write` 之后报文没立刻发出去" |

> 关联笔记：`AUTOSAR_CAN_Stack.md`

---

### 阶段三：驱动核心（BSW 立身之本）

#### 第 3 章 · MCAL

MCAL 是 BSW 工程师最核心的能力。建议按模块逐个攻破：

| 模块 | 学习目标 | 动手验收 |
|---|---|---|
| **Port / Dio** | 懂引脚复用配置、Port 与 Dio 的分工 | 配一个引脚做 GPIO 输出，点亮 LED |
| **Mcu** | 懂时钟树、三段式初始化、PCC 门控 | 改一次分频，观察外设行为变化 |
| **Adc** | 懂 Channel/Group/HwUnit、四种模式组合合法性 | 采一次电位器，串口/调试器读到值 |
| **Pwm** | 懂周期与占空比、PwmChannel 与 Port 的绑定 | 做呼吸灯 |
| **Spi** | 懂 Channel/Job/Sequence 三层、IB vs EB、CS 时序 | 读到 SBC 寄存器值，逻辑分析仪看波形 |
| **Gpt** | 懂定时器通道与 OS Counter 的关系 | 配 1ms 定时器，验证中断频率 |

| 项 | 内容 |
|---|---|
| **学习目标** | 每个模块都能"配 → 生成 → 调 API → 看现象"；懂 MCAL 的 `_Init` / `_MainFunction` 调用约定 |
| **BSW 要点** | **何时候用 MCAL API，何时必须走 CDD**（标准接口满足不了的场景） |
| **过关判据** | 给你一个新外设（比如 ICU），能独立从零配出可工作的版本 |

> 关联笔记：`AUTOSAR_MCU_时钟配置.md`、`AUTOSAR_SPI_Handler_Driver.md`、`AUTOSAR_ADC_Driver.md`

---

### 阶段四：应用层接口

#### 第 4 章 · Application（含 5 个小节）

BSW 工程师不写业务，但**必须懂 SWC/RTE 接口才能联调**。逐节目标：

| 小节 | 学习目标 | 过关判据 |
|---|---|---|
| **1、Application 概述** | 懂 SWC、Runnable、Port、RTE 的关系 | 能画出"SWC ↔ RTE ↔ BSW"的连接图 |
| **2、SWC_SR_Runnable** | 懂 Sender-Receiver 通信 + Runnable 触发源（TimingEvent / OperationInvoked / DataReceived） | 能自己加一个 S/R 信号并跑通 |
| **3、CS 接口** | 懂 Client-Server 同步/异步调用，谁是 Server 谁是 Client | 能说清 Rte_Call 的阻塞与非阻塞差异 |
| **4、数值和结构体** | 懂数据类型映射（uint8/uint16）、结构体信号打包 | 能正确把结构体映射到位域信号 |
| **5、枚举和数组** | 懂枚举类型映射、数组型信号 | 能配一个数组信号并收发 |

| 项 | 内容 |
|---|---|
| **BSW 要点** | `Rte_Write` / `Rte_Read` / `Rte_Call` 的**执行上下文**（在哪个 Task 里跑） |
| **必看** | 先读目录里的 `Application课程学习注意事项必看.pdf` |

#### 第 5 章（第一轮）· 与 BCM 应用层联合编译测试练习

| 项 | 内容 |
|---|---|
| **学习目标** | 跑通车窗 / 转向灯两个 SWC；**每个报错都要搞懂原因**（RTE 没重生成 / MemMap 缺失 / 任务映射漏配） |
| **动手验收** | 编译通过 + 功能正确 + 能画出 `Dio → SWC → RTE → Pwm` 完整数据流 |
| **BSW 要点** | **联编暴露的问题才是真问题**——宏没生成、任务没挂 Runnable、接口对不上 |
| **过关判据** | 面试能讲清"这个 Runnable 谁触发的、信号走 S/R 还是 C/S" |

### 阶段五：系统核心

#### 第 7 章 · OS 操作系统

| 项 | 内容 |
|---|---|
| **学习目标** | Task（Basic/Extended）、调度策略（抢占/协作）、ISR 一类/二类、Resource 优先级天花板、Alarm/Counter、Event/Message |
| **动手验收** | 自己加一个 10ms Task，把某 Runnable 从 50ms 挪到 10ms，观察调度行为 |
| **BSW 要点** | **AUTOSAR OS 与 FreeRTOS 的三点本质区别**（静态配置 / 零动态内存 / 确定性） |
| **过关判据** | 能讲清"我的 100ms 周期任务是怎么被 Alarm 唤醒的" |

> 关联笔记：`AUTOSAR_OS_模块详解.md`

#### 第 6 章 · 看门狗

| 项 | 内容 |
|---|---|
| **学习目标** | 懂 SWC→RTE→WdgM→WdgIf→Wdg→HW WDOG 五层；三种监控（Alive / Deadline / Logical）；Local/Global 状态机 |
| **动手验收** | 配置一个 SE + Checkpoint，**故意不喂狗让它复位**，用 RCM_SRS 确认复位原因 |
| **BSW 要点** | 时间链不等式：`打点周期 < MainFunction 周期 < TriggerCondition < 硬件超时` |
| **过关判据** | 能解释"进入 EXPIRED 后为什么硬件会复位" |

> 关联笔记：`AUTOSAR_WdgM_看门狗协议栈.md`

### 阶段六：网络管理

#### 第 8 章 · CAN 网络管理（CanNm，tc275）

> 注意：这章是 **tc275（英飞凌 AURIX）平台**的资料，学习时**关注机制而非平台细节**。

| 项 | 内容 |
|---|---|
| **学习目标** | 懂 NM 状态机（Bus-Sleep / Prepare-Bus-Sleep / Network / Repeat-Message）；网络请求与释放机制；NM 报文（PNC 位）作用 |
| **动手验收** | 在 BCM 项目上，让两个节点同时上线/同时睡眠，观察总线负载变化 |
| **BSW 要点** | 理解 **CanSM ↔ CanNm ↔ ComM ↔ EcuM** 的协作关系 |
| **过关判据** | 能回答"整车下电时，为什么节点不会立刻断电" |

### 阶段七：存储与诊断（求职差异化）

#### 第 9 章 · NVM

| 项 | 内容 |
|---|---|
| **学习目标** | 懂四层栈：`Nvm → Fee → MemIf → Fls`；懂 Block、CRC、冗余存储、掉电保护 |
| **动手验收** | 配一个 Block 存参数，**断电重上电数据还在** |
| **BSW 要点** | NVM 写入是**异步 + 排队**的；写坏块如何处理 |
| **过关判据** | 能解释"为什么诊断故障码要存在 NVM 而不是 RAM" |

#### 第 10 章 · UDS

| 项 | 内容 |
|---|---|
| **学习目标** | 网络层 CanTp（分段/流控）；诊断服务 `$10 / $22 / $2E / $27 / $3E / $34 / $36 / $37`；NRC 否定响应码 |
| **动手验收** | 用 CANoe（或 PCAN + 脚本）发 `10 03` 切扩展会话，收到正响应；发一条非法请求，收到 NRC |
| **BSW 要点** | **这是求职分水岭**——JD 出现频率最高、候选人最少 |
| **过关判据** | 能画出"一次 `$22` 读数据请求从总线上来，到 DCM 处理，再回响应的完整链路" |

> 进阶：学完 UDS 顺手做 **Bootloader**（`$34/$36/$37` 刷写），它和 UDS 共用 CanTp，是同一批知识。

### 阶段八：安全通信

#### 第 11 章 · E2E

| 项 | 内容 |
|---|---|

| **过关判据** | 能回答"E2E 为什么能检出数据被篡改/丢帧" |

## 6. MCAL 学完就忘？三个可落地的方法

MCAL 有六个模块（Port/Dio/Mcu/Adc/Pwm/Spi），学完一个忘一个很正常——因为它们**每个都有独立的寄存器模型、配置项、API，互相之间联系弱**。你之前的笔记体系已经做得不错（6 篇都有），问题是**"学完就忘"的根因是：你把 MCAL 当"六个独立模块"学，而不是当成"一套能串起来的能力"**。

### 方法一：每次学新模块，都做一张"模块间关系图"

学完 Adc 后，问自己：
- Adc 配置里引用了 Mcu 的什么？（`AdcCpuClockRef` → Mcu 的 ClockReferencePoint）
- Adc 中断是 Cat1 还是 Cat2？和 OS Counter 有什么关系？
- Adc 结果能被 Dio 读出来吗？不能，因为一个是模拟、一个是数字——它们的边界在哪？

学完 Spi 后，问：
- Spi 的 CS 片选能不能绑到 Pwm？不能，因为 CS 是 GPIO 控制、Pwm 是定时输出——**Pwm 和 Dio 谁管引脚？**
- Spi 的 EB 模式要 `Spi_SetupEB`，这个调用和 Mcu 时钟有什么间接关系？

**把这些"模块之间怎么串"画成一张图**——你就不是在学六个独立模块，而是在学**一套硬件抽象层**。这种串联式记忆，忘一个模块时其他模块会帮你回忆。

### 方法二：用"判别性实验"替代"看完视频"

你之前 SPI 调试用的"全 0x00 / 全 0x55"就是判别性实验——**这个方法是对抗遗忘的最强武器**。

学完任何 MCAL 模块，**必须亲手做 2~3 个 yes/no 实验**，而不是"看完视频配好就行"：

| 模块 | 判别性实验 | 为什么能记住 |
|---|---|---|
| Mcu | 改 PLL 分频 → 测 CAN 波特率跟着变 | 直接体验"时钟一变，所有外设都变"——你**亲手验证了时钟树的核心地位**，不是听来的 |
| Adc | 改 Channel 绑定的 GPIO → 读值立即变 | 记住了 AdcChannel 和 PortPin 的绑定关系 |
| Spi | 改 `SpiCsContinous` → 逻辑分析仪立即对齐 | 记住了 CS 时序和帧边界的关系——**你吃过这个坑** |
| Pwm | 改占空比 → LED 亮度变 | 记住了 Pwm 的 duty 单位 |
| Port/Dio | 改输入/输出方向 → 立即能/不能写 | 记住了 Port 和 Dio 的分工（Port 配方向/Dio 读写） |

**亲身踩过的坑 > 看过的视频 > 笔记里的文字**——这是记忆强度的顺序。

### 方法三：把每个 MCAL 模块"压缩成一张"面试卡

你现在 6 篇笔记都有，但每篇都比较长。**每周日花 10 分钟，把本周学的 MCAL 模块压缩成 5 行面试卡**：

```
【SPI 面试卡】
1. 三层模型：Channel ⊂ Job ⊂ Sequence
2. IB/EB 区别：IB 内部缓冲、EB 外部缓冲（必须每次 SetupEB）
3. 高频坑：SpiCsContinous=TRUE 导致 CS 全程低、分析仪无帧边界
4. 一个典型错误：EbMaxLength 配 4 以为是实发长度，实际是上限校验
5. 和 OS 的关系：SPI 中断是 Cat1（只清标志）还是 Cat2（要 SetEvent 唤醒 Task）
```

**周日自测时，面试卡是"最低通过线"**——讲不出这 5 行 = 还没记住，下周二前必须复习。笔记是"详细版本"，面试卡是"提取版本"——**压缩的过程本身就是记忆**。

### 最后一个心态提醒

MCAL 忘不是你的问题——**MCAL 就是该忘的**，它是"工具"，不是"知识"。你不会记住螺丝刀的每个细节，但你会记住"什么时候用螺丝刀、螺丝刀不能当锤子用"。

对你来说，**MCAL 最重要的不是记住 API 名字，而是记住三个东西**：
1. **模块之间怎么串**（Port 配引脚方向 → Dio 读写、Mcu 时钟 → 所有外设配置参数）
2. **高频坑**（PCC 门控没开、tick 当毫秒、CS 时序）
3. **面试卡点**（三层模型、IB/EB、优先级天花板）

API 名字忘了就查笔记——**工具是用来查的，不是用来背的**。

## 8. 各模块熟练标准（L1~L4 能力分层）

### 8.1 统一能力分层框架（1-3 年经验硬标准）

把 BSW 能力分成 **4 层**，面试角度：**L1 不会直接挂，L3 能区分候选人，L4 是资深岗才要求**。

| 层级 | 名称 | 本质 | 面试信号 | 占比 |
|---|---|---|---|---|
| **L1 概念层** | 能说清"这模块解决什么问题、怎么工作" | 底层逻辑 | ✅ 必须会——讲不清直接挂 | 30% |
| **L2 配置层** | 能在 DaVinci 里**从零配出一个可用的实例** | "会用"的硬标准 | ✅ 必须会——面试官让你现场改配置时不慌 | 40% |
| **L3 排错层** | 出问题能**定位到根因**（不是瞎改） | 1-3 年经验的核心区分点 | ✅ 必须会——面试官最爱问"遇到过什么坑" | 25% |
| **L4 原理层** | 能讲清**驱动内部/OS 内部怎么实现** | 资深岗才要求 | ⭕ 加分项——别说没用，但别花太多时间 | 5% |

**核心原则**：1-3 年经验，**L1+L2+L3 就够拿 15k~20k**，L4 暂时不用深入。

### 8.2 OS 模块熟练标准（你举的例子）

| 层级 | 必须/应该/暂时不用 | 具体内容 | 验证方法 |
|---|---|---|---|
| **L1 必须** | 概念 | Basic vs Extended 三能力差异、Cat1 vs Cat2 OS 可见性差异、Event 是 bit 不是函数、Resource 跨层锁调度的原因、Counter 是软件 tick 不是硬件 | 能嘴讲清楚，别卡壳 |
| **L2 必须** | 配置 | **从零新增一个 10ms Extended Task（含 Counter/Alarm/Event/OS 配置）**、配 Resource 保护共享变量、用 ErrorHook 调试、配 Schedule Table 实现多任务同步 | 动手验证：新增后能跑起来、ErrorHook 能逮到"Task 没 TerminateTask" |
| **L3 必须** | 排错 | 能定位「Task 永远 WAITING」（没 SetEvent？Alarm 没启动？EventMask 配错？）、「ISR 调 OS API 报错」（Cat1 当成 Cat2？）、「Counter tick 不准」（PIT 中断周期配错？） | 故意制造错误（删 Alarm、改 Cat2 成 Cat1），3 分钟内定位根因 |
| **L4 暂时不用** | 原理 | OS 调度器内部怎么选最高优先级 Task、优先级天花板在 Os_Internal.c 里怎么实现 | 别花时间，面试不会问 |

### 8.3 MCAL 六模块熟练标准（统一要求 L1+L2+L3）

| 模块 | L2 必须会的配置动作 | L3 必须会的排错 |
|---|---|---|
| **Mcu** | 改 PLL 分频、改时钟源切换、引用 ClockReferencePoint | 改分频后 CAN 波特率跟着变（自己验证）、忘开 PCC 门控导致外设寄存器写不进 |
| **Spi** | 配 EB 模式、改 SpiCsContinous、配 Channel/Job/Sequence 三层 | 逻辑分析仪解码错（CS 全程低？采样边沿配错？）、SetupEB 报长度错误（EbMaxLength 配太小？） |
| **Adc** | 配 Group/Channel、改触发源（软件/GPT）、配连续采样 | 读值乱跳（Channel 绑错 GPIO？参考电压没开？）、中断过重导致其他任务不跑（你吃过的坑） |
| **Can** | 配波特率、配 HTH/HRH、启用中断 | CANoe 发报文没响应（波特率不匹配？HRH 没配？）、总线 off（硬件问题？波特率严重不匹配？） |
| **Pwm** | 改占空比、改周期、输出引脚 | 输出一直高/低（引脚复用错？PWM 周期配太小？） |
| **Port/Dio** | 改引脚方向（输入/输出）、读写引脚 | 能写不能读（方向配反了？）、引脚复用冲突（Port 没设对？） |

### 8.10 面试自测清单（每个模块结束时过一遍）

必须全部通过才算"熟练"：
1. ✅ **能嘴讲**：合上笔记，把模块核心概念讲一遍，别卡壳（L1）
2. ✅ **能动手**：从零配一个实例（比如 OS 新增 Task、SPI 新增 EB 读命令），**能跑起来**（L2）
3. ✅ **能排错**：故意制造 2~3 个错误（比如删 Alarm、改 Cat2 成 Cat1），**3 分钟内定位根因**（L3）
4. ✅ **能踩坑**：有 1~2 个自己亲手踩过的坑（比如 SPI CS 全程低、ADC 中断过重），能讲清**现象→排查路径→根因→修复**（L3）

过不了的处理方式：
- L1 讲不清 → 回去看概念笔记
- L2 动手失败 → 按"工程落地步骤"一步步走，别跳步
- L3 排错慢 → 按"常见坑"清单逐个验证
- 没踩过坑 → 故意制造一个错误，让自己踩一次（比看视频管用 10 倍）
